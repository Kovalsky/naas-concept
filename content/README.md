# `content/` — спільне джерело контенту НААН (майбутня БД)

Нейтральний шар, яким **не володіє жоден сайт**. Усі версії дизайну (`site/` Gravitas, `site-light/` Light і наступні) тягнуть контент звідси через alias `@content/*`. Одна правка тут — оновлює всі сайти.

## Структура

| Шлях | Що це | Формат |
|---|---|---|
| `data/*.json` | Структуровані «таблиці»: особи, установи, контакти, анонси, новини, реєстри, секції, відео, е-бібліотека, агролекції, документи, ресурси | чисті дані |
| `pages/*.md` | Довгі тіла сторінок (статут, майнові питання, рада молодих, наан-сьогодні…) | Markdown |
| `i18n.ts` | UI-рядки `STRINGS{uk,en}` + `t()` | модуль |
| `site.ts` | Маршрути, нав, підвал, партнери, showcase, пошуковий індекс | модуль |
| `registries.ts` | Реєстри документів + `byRoute()` + ліди | модуль (читає `data/registries.json`) |
| `schema.ts` | **Контракт даних** (zod) — модель майбутньої CMS | модуль |
| `index.ts` | Бочка-фасад: `@content` | модуль |

## Як споживають сайти

- tsconfig обох сайтів: `"@content/*": ["../content/*"]`.
- Сторінки/компоненти імпортують `@content/...` (або через тонкі шими `src/lib/*`, що ре-експортують `@content`).
- Колекції контенту (`content.config.ts`) вантажать `../content/pages/*.md` і `../content/data/news.json`.

## Принцип портативності (для переїзду на CMS / інший фреймворк)

Контент зберігається **як дані, а не як код**, за **стабільним фасадом**. Щоб змінити сховище (файли → CMS API) — переписують лише модулі тут; сайти не змінюються. `schema.ts` стає моделлю контенту CMS.

## Межі (Phase 0)

- Перенесено: дані, тіла сторінок, `i18n/site/registries`.
- Поки **в сайтах**: site-специфічні хелпери (`src/lib/data.ts` derivations, `format.ts`, light `images.ts`/`config.ts`).
- **Розходжений** per-page контент (meta/hero, домашній hero, бренд, картки) — уніфікується у Phase 1 (`content.json`) після узгодження канону.
- Зображення поки лишаються в `site/public/img` (спільні через реальний сусідній шлях) — кандидат на `content/assets/` пізніше.
